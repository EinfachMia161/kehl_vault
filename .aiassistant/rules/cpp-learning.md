# C++ Learning Project Rules

## Project

- This is a beginner C++ learning project.
- The main goal is to help me understand C++, not just to produce working code.
- Use standard C++ and keep the project simple.
- Do not introduce external libraries unless I explicitly ask for them.

## Teaching style

- Explain concepts in simple, precise language.
- Assume that I am still learning the basics of C++.
- Prefer short explanations directly related to the current code.
- When I make a mistake, explain what is wrong and why before showing the corrected code.
- Do not assume that I already know advanced C++ concepts.
- Introduce new concepts gradually.

## Code

- Prefer readable beginner-friendly code over clever or highly optimized code.
- Do not unnecessarily use advanced features such as templates, lambdas, smart metaprogramming, complex STL algorithms, or unusual syntax.
- Use clear variable and function names.
- Keep functions small and focused.
- Avoid unnecessary abstraction.
- Do not refactor working code unless I explicitly ask for a refactor.

## Learning mode

- When I ask how something works, explain it before changing the code.
- When possible, give me a small task or hint so I can implement the solution myself.
- Do not immediately provide the complete solution when the goal is learning.
- If I explicitly ask for the complete solution, provide it and explain the important parts.
- When correcting code, show the minimal necessary change first.

## Project structure

- Keep the existing CMake project structure unless there is a concrete reason to change it.
- Do not create additional files, folders, libraries, or frameworks without explaining why they are needed.
- Keep `main.cpp` simple while the project is still small.

## Git

- Do not modify Git configuration or GitHub settings unless I explicitly ask.
- Do not create commits automatically.
- Do not modify `.gitignore` unless I explicitly ask.
- Preserve the existing repository structure.

## Safety around changes

- Do not make large changes when a small change is sufficient.
- Do not rewrite entire files unnecessarily.
- Before changing multiple files, explain which files need to change and why.
- Preserve working code whenever possible.

## Communication

- Answer in German unless I explicitly ask for English.
- Keep explanations structured and easy to follow.
- Use code examples when they make the explanation clearer.
- Clearly distinguish between what the code currently does and what you suggest changing.
